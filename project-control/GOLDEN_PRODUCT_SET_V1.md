# Golden Product Set V1

Golden Product Set V1 is the canonical documentation/fixture baseline for future Product Understanding, Digital Product Identity, Visual Consistency, slot-lineage, provider-comparison, and image-regression work. Its operational corpus lives in `project-control/golden-product-set-v1/`.

## Materialized baseline

The intended distribution remains the 36-product VCE proposal with 12 loafers. A deterministic local scan found only one defensible tracked product-reference candidate, `public/products/kahve-deri.jpg`. It is materialized as `gpsv1-0001`, a draft lifestyle-sneaker calibration record. It has no operator-approved facts or Locked Fact Set. Originality, rights, owned-product linkage, and family still require human confirmation.

Seven storefront hero assets, one screenshot, seven temporary video frames, and twelve build artifacts were excluded. Hero morphology was not used to fill loafer counts because decoration use and visual resemblance do not prove canonical product provenance. Exact paths, hashes, and reasons are recorded in the inventories.

Current counts: 1 materialized, 0 approved, 0 loafers, 35 products missing. Readiness is `blocked_missing_source_references`.

## Canonical rules

- Layer A original references and attributable human-reviewed annotations define product truth.
- Layer B generated outcomes are a future evaluation archive with no identity-truth authority.
- Generated, approved-generated, rejected-generated, screenshot, temporary, customer, production-only, and undocumented media cannot enter Layer A.
- Not visible is not absent; unknowns and disputes remain explicit.
- Machine/repository audits may draft but cannot review, approve, or lock facts for an operator.
- Approved annotations are versioned append-only evidence; correction supersedes rather than silently overwrites.
- Stable semantic slot purposes may appear in risk expectations, but array positions are never durable identity.
- Failure taxonomy policy is advisory in V1; it does not add a runtime generation or publication gate.

## Annotation model

Each selected product records source provenance/hash/classification/sanitization, family evidence and confusion candidates, a 15-region Reference Sufficiency Map, a deterministic-fingerprint contract, a conservative Locked Fact Set, domain facts with state/provenance/confidence/evidence, explicit unknowns and prohibited assumptions, source quality, expected failure codes/checks/slot risks, loafer-specific fields when applicable, operator notes, and reversible review history.

The schemas enforce stable IDs and versions, original-only Layer A sources, portable paths, explicit review states, human attribution for reviewed/approved records, approval authority, loafer detail requirements, and non-positional slot expectations. A repository script using the already-installed Ajv validates schemas, references, bytes, hashes, counts, families, review rules, duplicates, leaks, and version consistency without package changes or installs.

## Relationship to canonical image specifications

- `PRODUCT_UNDERSTANDING_LAYER_V1.md` supplies fact provenance, Reference Sufficiency, fingerprint, unknown, and Locked Fact Set semantics.
- `VISUAL_CONSISTENCY_ENGINE_V1.md` supplies the exact 36/12 distribution, cross-slot comparison intent, durable identity principles, and loafer priority.
- `IMAGE_GENERATION_BLUEPRINT_V1.md` supplies immutable attempt/slot lineage, versioning, migration, and no-compaction invariants.

The corpus does not implement any of these runtime designs and does not change prompts, cameras, slot purposes, providers, generation, approval, publishing, or production systems.

## Calibration, holdout, and privacy

At full size, use 24 calibration products (8 loafers) and a sealed 12-product holdout (4 loafers). Detailed holdout answers remain with the operator/independent evaluator during development. Provider/prompt/profile comparisons shuffle outputs, hide system identity, score identity before aesthetics, preserve stable product/slot IDs, and seal decisions before unblinding.

The selected source contains no detected EXIF, GPS, PII, person, private path, credential, or production URL. Its WebP payload has a `.jpg` filename; this is explicitly recorded. No binary was duplicated because the manifest pins the existing tracked path and hash.

## Acceptance and next task

The corpus is structurally valid but not suitable for visual-quality calibration or regression enforcement. Quality-calibration readiness requires original/sanitized references, sufficient loafer coverage, operator-reviewed initial calibration records, complete provenance/unknowns, passing integrity checks, and deterministic fixture usability. Regression enforcement additionally requires the full reviewed distribution, sealed holdout, evaluator definitions, baselines, and approved reporting governance.

The exact next runtime implementation task—only after separate authorization, but independently of the still-blocked visual-quality corpus gate—is **Pure Metadata Contracts and Durable Slot Identity Foundation**: introduce canonical slot IDs, non-positional failure-preserving per-slot records, immutable attempt identifiers, versioned metadata contracts, and legacy compatibility under tests, with no prompt, camera, slot-purpose, provider, or generation-quality changes.
